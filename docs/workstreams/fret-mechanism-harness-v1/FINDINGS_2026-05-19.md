## F200: Workspace shell tabstrip overflow gate exposed tab-cycle policy drift

Layer: UI Gallery workspace shell policy plus `fret-workspace` tab state API.

Status: runtime gate complete. A UI Gallery consumer-policy defect was fixed.

What was found:

- The new workspace tabstrip overflow gate needed a constrained-but-not-collapsed width. At
  `420 x 720`, the top-bar center column and tabstrip width collapsed to zero, so the script could
  not observe the overflow button. At `900 x 720`, the tabstrip overflows while preserving a
  positive center width.
- The overflow gate passed by itself, but adding it to the existing `ui-gallery-workspace-shell`
  suite exposed a separate real behavior drift in the old tab-command smoke:
  `workspace.tab.next` handled by `WorkspaceCommandScope` used the workspace crate default MRU
  cycle and selected Overlay after starting from Field.
- That differed from the Gallery driver fallback and existing focused Gallery expectation, which
  use visible-order cycling for this single-pane page-tab shell. The failure was not caused by the
  new overflow gate; it was a runtime scope path that the suite now made visible.

What was changed:

- Added `WorkspaceTabs::set_cycle_mode` so consumer layouts can change tab-cycle policy without
  reconstructing tab state.
- Set UI Gallery's single-pane workspace layout to `TabCycleMode::InOrder` during layout creation
  and treat non-`InOrder` Gallery workspace layouts as unsupported so model/layout sync rebuilds
  them consistently.
- Added `workspace_layout_tab_next_uses_gallery_visible_order`, which applies
  `workspace.tab.next` directly to the Gallery `WorkspaceWindowLayout`, then renders a frame and
  proves the selected page, layout snapshot, and router advance from Field to Command.
- Added `ui-gallery-workspace-tabstrip-overflow-select-command.json`, promoted it into
  `ui-gallery-workspace-shell`, and added protocol roundtrip coverage.
