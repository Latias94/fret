## F200: Workspace shell tabstrip overflow gate exposed tab-cycle policy drift

Layer: UI Gallery workspace shell policy plus `fret-workspace` tab state API.

Status: runtime gate complete. A UI Gallery consumer-policy defect was fixed.

What was found:

- The new workspace tabstrip overflow gate needed a constrained-but-not-collapsed width. At
  `420 x 720`, the top-bar center column and tabstrip width collapsed to zero, so the script could
  not observe the overflow button. At `900 x 720`, the tabstrip overflows while preserving a
  positive center width.
- The overflow gate passed by itself, but adding it to the existing `ui-gallery-workspace-shell`
  suite exposed a separate real behavior drift in the old tab-command smoke:
  `workspace.tab.next` handled by `WorkspaceCommandScope` used the workspace crate default MRU
  cycle and selected Overlay after starting from Field.
- That differed from the Gallery driver fallback and existing focused Gallery expectation, which
  use visible-order cycling for this single-pane page-tab shell. The failure was not caused by the
  new overflow gate; it was a runtime scope path that the suite now made visible.

What was changed:

- Added `WorkspaceTabs::set_cycle_mode` so consumer layouts can change tab-cycle policy without
  reconstructing tab state.
- Set UI Gallery's single-pane workspace layout to `TabCycleMode::InOrder` during layout creation
  and treat non-`InOrder` Gallery workspace layouts as unsupported so model/layout sync rebuilds
  them consistently.
- Added `workspace_layout_tab_next_uses_gallery_visible_order`, which applies
  `workspace.tab.next` directly to the Gallery `WorkspaceWindowLayout`, then renders a frame and
  proves the selected page, layout snapshot, and router advance from Field to Command.
- Added `ui-gallery-workspace-tabstrip-overflow-select-command.json`, promoted it into
  `ui-gallery-workspace-shell`, and added protocol roundtrip coverage.

## F201: Workspace shell demo tab movement now preserves dragged-tab ownership

Layer: `fret-workspace` tab-strip commands and workspace shell demo diagnostics.

Status: runtime mechanism fix complete; final rebuilt-suite failure was a command ownership
double-application defect in the demo shell.

What was found:

- The workspace shell demo suite exposed a real ownership hazard in tab drag/reorder: tab-strip
  reorder intents still dispatched active-tab move commands, so a drag path that changed activation
  during the gesture could move the wrong tab.
- End-drop was also symbolic until late in the path. Runtime traces needed a concrete target such
  as `workspace.tab.move_after_id.7:doc-a-0doc-a-2`, not a command whose effect depended on the
  active tab at application time.
- Local tab-strip drag state was tied to subtree-local model identity. Under overflow/scroll
  rebuilds, that could lose the local drag snapshot before the drop target consumed it.
- The final failing overflow reorder script was not a runtime reorder defect. It dragged from the
  clipped `doc-a-0` semantic bounds edge. The corrected script selects `doc-a-0` through overflow,
  waits for the active tab to become visible, then drags to `drop_end`.
- The rebuilt full suite then exposed a separate app-shell ownership defect. The workspace shell
  demo runner applied `workspace.*` commands to its app-owned model first, but
  `WorkspaceCommandScope` replayed the same command to the same model afterward. Non-idempotent
  commands such as `workspace.tab.toggle_pin` could therefore run twice, committing the preview but
  leaving the tab unpinned.

What was changed:

- Added length-prefixed specific-tab move commands:
  `workspace.tab.move_before_id.<dragged_len>:<dragged><target>` and
  `workspace.tab.move_after_id.<dragged_len>:<dragged><target>`.
- Added `WorkspaceTabs::move_tab_relative_to`, preserving the existing active-tab command family
  while giving drag/drop a command that names the dragged tab explicitly.
- Changed tab-strip reorder intents and end-drop handling to resolve `End` into a concrete
  after-target in canonical order and dispatch the specific-tab move command.
- Moved local and pane-tree tab drag models to stable window/root keys so drag state survives
  tabstrip subtree rebuilds.
- Added an explicit `WorkspaceCommandScope::apply_workspace_model_commands(false)` mode so
  app-owned shells can keep focus-transfer command hooks without replaying model commands already
  applied by the runner.
- Updated the workspace shell demo tab-strip host to use auto height and wrapping so the constrained
  overflow gate keeps the controls reachable.
- Hardened the overflow activation and overflow reorder scripts, then promoted the relevant
  workspace-shell-demo roundtrip coverage.
