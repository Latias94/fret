## F289: Drawer Demo relation/action-state now targets the actual dialog content

Context:

- Fret Drawer is a Sheet-backed recipe with Drawer-specific drag and motion wrappers.
- Sheet relation/action-state coverage had already fixed generic trigger `expanded/controls` and
  modal title/description registration for direct SheetContent paths.
- Drawer still needed its own runtime gate because the returned content tree is not always the
  concrete dialog content node: Drawer wraps content for drag/settle behavior before Sheet applies
  trigger a11y.

What was found:

- A real Sheet-backed Drawer semantics gap was reproduced in a focused unit regression.
- The Drawer trigger's `controls` relation could point at the outer drag/motion wrapper instead of
  the actual `role=dialog` DrawerContent node.
- DrawerContent itself stamped `role=dialog` but did not read the modal a11y scope, so content
  `labelled_by` / `described_by` relations were missing even when DrawerTitle and
  DrawerDescription were present.

What changed:

- Sheet's generic trigger a11y target selection now prefers the first returned content-tree element
  with `SemanticsRole::Dialog`, while preserving the previous returned-root fallback.
- DrawerContent now reads `modal_relations_for_current_scope(...)` and attaches `labelled_by` /
  `described_by` relationships together with its dialog role.
- The Drawer Demo snippet now gives its dialog title/description stable, dialog-specific test ids.
- Added `ui-gallery-drawer-demo-relation-action-state.json`, promoted it into a dedicated
  `ui-gallery-drawer-relation-action-state` suite, and added protocol roundtrip coverage.
