# Findings

## F1: Suppressed-boundary dirty child removal can look like a component parity bug

Layer: `crates/fret-ui` mechanism

Status: fixed before this lane, now promoted into fixture-driven mechanism coverage

What was found:

- The UI Gallery checkbox "Enable notifications" label toggle previously exposed subtree layout
  dirty count underflow.
- The root cause is mechanism-level: a child dirty delta from work hidden behind
  `layout_dirty_children_suppressed` must not be applied to ancestors that intentionally did not
  aggregate that child work.
- The user-visible symptom looked like checkbox or field layout instability, but the owner is dirty
  aggregation and subtree removal.

Regression coverage:

- Focused tests: `crates/fret-ui/src/tree/tests/subtree_layout_dirty_underflow_repair.rs`
- Fixture suite: `crates/fret-ui/src/tree/tests/fixtures/layout_dirty_invalidation_v1.json`
- Fixture runner: `crates/fret-ui/src/tree/tests/layout_dirty_invalidation_harness.rs`
- Runtime script:
  `tools/diag-scripts/ui-gallery/checkbox/ui-gallery-checkbox-demo-with-title-toggle-underflow.json`

Next slice:

- Extend the same fixture model to retained/declarative cache root transitions and scroll-contained
  dirty frontiers, because those paths also use "dirty descendant exists, but should/should not cross
  a boundary" reasoning.

## F3: Scroll-handle window-update needed a cache-root-oriented harness, not an invalidation-walk harness

Layer: `crates/fret-ui` mechanism harness

Status: fixed in this slice as harness coverage, no runtime defect found

What was found:

- Scroll-handle window-update is not a plain invalidation-walk fact. The key mechanism is the chain
  from scroll-handle registry change classification, to live bound-node filtering, to nearest
  view-cache root dirtying or reuse.
- The first fixture attempt incorrectly expected `ScrollHandleWindowUpdate` to appear as an
  invalidation-walk detail. The runtime records the important result on the cache-root dirty/reuse
  surface instead.
- The runtime behavior matched the expected invariants in this run; no new `fret-ui` mechanism bug
  was exposed.

What was fixed:

- Added a dedicated scroll-handle invalidation fixture suite:
  `crates/fret-ui/src/tree/tests/fixtures/scroll_handle_invalidation_v1.json`.
- Added a thin runner:
  `crates/fret-ui/src/tree/tests/scroll_handle_invalidation_harness.rs`.
- The runner now observes scroll-handle change deltas, invalidation-walk deltas, node dirty flags,
  cache-root dirty membership, and view-cache reuse as scalar mechanism metrics.
- The fixture matrix covers:
  - windowed scroll offset changes dirtying cache roots;
  - revision-only bumps after internal offset updates staying reusable for generic windowed scroll;
  - virtual-list window escape dirtying cache roots;
  - virtual-list revision-only window escape still forcing a window update;
  - detached same-frame stale scroll bindings being filtered before invalidation.

Regression coverage:

- Fixture suite: `crates/fret-ui/src/tree/tests/fixtures/scroll_handle_invalidation_v1.json`
- Fixture runner: `crates/fret-ui/src/tree/tests/scroll_handle_invalidation_harness.rs`
- Focused view-cache tests: `crates/fret-ui/src/tree/tests/view_cache.rs`
