## F137: Tailwind flex-1 now uses percent basis semantics in Fret UI kit

Layer: `fret-ui-kit` layout utility policy backed by `fret-ui` layout mechanism fixture coverage.

Status: observed and fixed.

What was found:

- The remaining `ui-gallery-select-label-trigger` zero-size warning was not a Select-only
  accessibility or trigger semantics issue. The upstream shadcn `FieldContent` source uses
  `flex flex-1 flex-col gap-1.5 leading-snug`, while the Fret `LayoutRefinement::flex_1()` helper
  translated `flex-1` as a hard `0px` basis.
- CSS/Tailwind `flex-1` is `flex: 1 1 0%`, not `flex: 1 1 0px`. In an indefinite main axis, the
  percent basis behaves like content/auto, while a hard `0px` basis can collapse content-bearing
  vertical compositions and report zero-size descendants.
- This exposed a harness gap: the Select runtime gate could find the symptom, but the layout
  primitive harness did not yet lock the underlying auto-height vertical flex invariant.

What was fixed:

- Changed `LayoutRefinement::flex_1()` from `LengthRefinement::Px(0px)` to
  `LengthRefinement::Fraction(0.0)` so the utility matches Tailwind/CSS percent basis semantics.
- Added a `fret-ui-kit` unit test that locks the `flex-1` translation to `grow=1`, `shrink=1`,
  `basis=0%`.
- Added a `fret-ui` layout primitive fixture case for an auto-height vertical flex stack with a
  `grow/shrink + 0% basis` content item followed by a fixed-height sibling. The oracle proves the
  content item remains 10px high, the fixed sibling remains 36px high, and the parent stack resolves

## F138: Timer dispatch now ignores stale targets on hidden overlay layers

Layer: `fret-ui` event dispatch mechanism.

Status: observed and fixed.

What was found:

- The `ui-gallery-select-typeahead-commit-banana` runtime gate passed visually, but emitted repeated
  `dispatch/chain: node missing from input snapshot` warnings when the Select typeahead clear timer
  fired after the listbox had closed.
- The warning exposed a real mechanism defect: targeted timer dispatch resolved a live attached
  element/node even when that node belonged to a hidden overlay layer. The timer dispatch context is
  intentionally built from visible layers so transition-visible, hit-test-inert layers can still
  receive timers. Hidden layers must not receive targeted timer dispatch.
- In the failing reduced mechanism case, a hidden overlay timer target received the timer and stopped
  propagation, preventing visible timer listeners from seeing the event. That made the issue more
  than logging noise.

What was fixed:

- Timer target resolution now verifies the resolved node is present in the timer dispatch snapshot
  before targeted dispatch. If it is not in the visible-layer snapshot, the target is treated as
  missing and the normal visible-layer broadcast path continues.
- Added a regression test where a hidden overlay owns the stale timer target and the visible base
