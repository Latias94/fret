# Fret Mechanism Harness v1 Findings

## F129: Layout primitive synthetic coverage expanded without exposing a new mechanism defect

Layer: declarative layout mechanism harness.

Status: observed and documented.

What was found:

- The existing `layout_primitives_v1.json` suite covered only a narrow slice of layout behavior.
- The largest remaining gap was not a known runtime bug, but missing synthetic proof for several
  self-drawn layout primitives that commonly affect shadcn-style composition: percent sizing,
  min/max clamping, intrinsic measurement with percent constraints, wrapped text height
  propagation, scroll-root child layout preservation, and absolute percent inset placement.
- The baseline `mechanism_harness_layout_primitives_match_oracles` test was already green, so the
  right move was to widen the harness before claiming any new defect.

What was fixed:

- Added new fixture cases for percent sizing, min/max clamping, percent min/max intrinsic
  measurement, wrapped text height propagation, scroll-root child layout preservation, and
  absolute percent inset placement.
- Upgraded the layout primitive test harness with a test-local text service that can model wrap
  width and line growth instead of a fixed 10x10 placeholder.
- Added scalar metric collection for the intrinsic percent min/max case so the fixture can assert
  measurement behavior without overloading geometry assertions.

Evidence anchors:

- `crates/fret-ui/src/declarative/tests/layout/mechanism_harness.rs`
- `crates/fret-ui/src/declarative/tests/fixtures/layout_primitives_v1.json`
- `docs/workstreams/fret-mechanism-harness-v1/COVERAGE_MAP.md`
- `docs/workstreams/fret-mechanism-harness-v1/EVIDENCE_AND_GATES.md`

Run results:

- Focused synthetic gate:
  `cargo test --profile dev-fast -p fret-ui --lib mechanism_harness_layout_primitives_match_oracles -- --nocapture`
  - Result: passed.

Next slice recommendation:

- Add text measurement/paint agreement cases or explicit RTL/writing-mode cases once the direction
  contract is clear enough to exercise as a synthetic mechanism slice.

## F130: Text measurement/paint agreement promoted into the layout primitive harness

Layer: declarative layout mechanism harness.

Status: observed and documented.

What was found:

- Fret already had focused Rust tests proving that text measurement and paint preparation agree on
  wrap width, overflow, and scale factor.
- The durable mechanism harness did not observe those facts, so `layout_primitives_v1.json` could
  prove wrapped layout height but not whether the measure pass and paint pass used the same text
  constraints.
- That is a harness gap for a self-drawn UI engine: a component can appear misaligned when layout
  used one wrap width and paint used another, even if the final node bounds look plausible.

What was fixed:

- Added fixture cases for column text wrap-width agreement, max-width row wrap-width agreement, and
  overflow/scale constraint agreement.
- Extended the layout primitive observer to paint selected scenarios and publish scalar metrics for
  measured-vs-prepared wrap width, scale factor, overflow/wrap equality, prepared painted height,
  and following-sibling placement after painted text height.
- Kept the changes in the mechanism harness layer; no runtime behavior was changed.

Evidence anchors:

- `crates/fret-ui/src/declarative/tests/layout/mechanism_harness.rs`
- `crates/fret-ui/src/declarative/tests/fixtures/layout_primitives_v1.json`
- `docs/workstreams/fret-mechanism-harness-v1/COVERAGE_MAP.md`

Run results:

- Focused synthetic gate:
  `cargo test --profile dev-fast -p fret-ui --lib mechanism_harness_layout_primitives_match_oracles -- --nocapture`
  - Result: passed.

Next slice recommendation:

- Add RTL/writing-mode layout primitive cases only after the mechanism-level direction model is
  explicit enough to avoid baking recipe policy into `fret-ui` oracles.

## F131: View-cache lifecycle promoted into a fixture-driven mechanism harness

Layer: declarative view-cache and layout-query invalidation mechanism.

Status: observed and documented.

What was found:

- No new runtime mechanism defect was reproduced in this slice.
- The useful finding was a harness modeling gap: key `ViewCache` lifecycle guarantees were covered
  by scattered focused tests, but not by a single fixture-driven matrix that future agents can
  extend case-by-case.
- The first layout-query oracle draft also clarified an important mechanism rule: layout-query reads
  are frame-lagged, so a size change must not rerender the dependent cached subtree in the same
  frame; it should rerender after the committed layout-query revision advances.

What was fixed:

- Added `view_cache_lifecycle_v1.json` with stable case ids for clean cache hits, element state
  preservation, explicit cache-key misses, animation-frame invalidation, model dependency
  preservation across cache-hit frames, unrelated model scoping, inspection-mode cache bypass, and
  layout-query next-frame invalidation.
- Added a thin `view_cache_lifecycle_harness.rs` runner that reports scalar render, cache-reason,
  model-observation, state, and layout-query metrics through `fret-mechanism-harness`.
- Kept the change in the mechanism harness layer; no runtime behavior was changed.

Evidence anchors:

- `crates/fret-ui/src/declarative/tests/fixtures/view_cache_lifecycle_v1.json`
- `crates/fret-ui/src/declarative/tests/view_cache_lifecycle_harness.rs`
- `crates/fret-ui/src/declarative/tests/mod.rs`
- `docs/workstreams/fret-mechanism-harness-v1/COVERAGE_MAP.md`
- `docs/workstreams/fret-mechanism-harness-v1/EVIDENCE_AND_GATES.md`

Run results:

- Fixture schema:
  `python -m json.tool crates/fret-ui/src/declarative/tests/fixtures/view_cache_lifecycle_v1.json > $null`
  - Result: passed.
- Focused synthetic gate:
  `cargo test --profile dev-fast -p fret-ui --lib mechanism_harness_view_cache_lifecycle_matches_oracles -- --nocapture`
  - Result: passed.
- Companion view-cache focused gate:
  `cargo test --profile dev-fast -p fret-ui --lib view_cache -- --nocapture`
  - Result: passed.

Next slice recommendation:

- Move to a runtime-visible scroll/click stability slice or a retained/component semantics mutation
  slice. Add a UI Gallery companion for view-cache lifecycle only if a real surface can mutate
  cached model/layout-query dependencies in a way synthetic fixtures cannot represent.

## F132: ScrollArea content-growth runtime gate promoted into the suite

Layer: UI Gallery diagnostics harness for scroll extent and click stability.

Status: observed and documented.

What was found:

- No ScrollArea mechanism defect reproduced in the focused run.
- The actual gap was harness promotion: `ui-gallery-scroll-area-expand-at-bottom.json` already
  encoded the risky runtime behavior, but it was not a member of the promoted
  `ui-gallery-scroll-area` suite.
- This matters for a self-drawn UI framework because dynamic content growth can pass static layout
  fixtures while still failing at runtime if scroll extents, click targeting, or viewport stability
  drift after the content changes.

What was fixed:

- Added the content-growth script to `tools/diag-scripts/suites/ui-gallery-scroll-area/suite.json`.
- Added a `fret-diag-protocol` roundtrip test so the promoted script stays parseable through the
  diagnostics schema.
- Kept the change in the diagnostics harness layer; no runtime behavior was changed.

## F133: DataTable page-entry lint moved from candidate debt to strict coverage

Layer: diagnostics registry authoring harness.

Status: observed and documented.

What was found:

- No DataTable component or mechanism defect was reproduced in this slice.
- The earlier candidate audit reported 174 DataTable page-entry violations across 21 promoted
  scripts when DataTable was modeled as having only one owning page root.
- A second audit showed those were harness-modeling false positives: DataTable has several valid
  page/variant roots (`default`, `basic`, `listlike`, `reusable`, `rtl`, and `torture`) that prove
  page entry just as well as the broad page body id.

What was fixed:

- Extended the diagnostics registry page-entry lint to support `entry_ids` per page rule.
- Enabled strict page-entry lint for `ui-gallery-data-table`,
  `ui-gallery-data-table-retained`, and `ui-gallery-data-table-view-cache-torture`.
- Added lint self-tests for DataTable variant-root entry, missing entry rejection, and
  `FRET_UI_GALLERY_START_PAGE=data_table_torture` entry evidence.

Evidence anchors:

- `tools/check_diag_scripts_registry.py`
- `tools/test_check_diag_scripts_registry.py`
- `tools/diag-scripts/suites/ui-gallery-data-table/suite.json`
- `tools/diag-scripts/suites/ui-gallery-data-table-retained/suite.json`
- `tools/diag-scripts/suites/ui-gallery-data-table-view-cache-torture/suite.json`

Run results:

- Candidate audit before the fix:
  - Result: 174 DataTable candidate violations across 21 promoted scripts under a single-root
    model.
- Candidate audit after modeling DataTable entry roots:
  - Result: 0 DataTable candidate violations.
- Lint self-test gate:
  `python tools/test_check_diag_scripts_registry.py`
  - Result: passed, 11 tests.
- Registry gate:
  `python tools/check_diag_scripts_registry.py`
  - Result: passed.

Next slice recommendation:

- Extend strict click-visibility to one more promoted long-page family, or move back to a
  runtime-visible component suite where lint already has zero false positives.
