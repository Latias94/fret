# Findings 2026-05-12

## F4: WindowMetricsService environment changes did not reach view-cache environment dependencies

Layer: `crates/fret-ui` declarative runtime / environment mechanism

Status: fixed

What was found:

- Existing environment view-cache tests mostly wrote directly into `ElementRuntime`, while real
  desktop/web runners write platform environment updates into `WindowMetricsService`.
- `render_root` only synchronized viewport bounds, scale factor, safe-area insets, and occlusion
  insets from `WindowMetricsService` into `ElementRuntime`.
- As a result, view-cache subtrees that queried color scheme, reduced motion, text scale, reduced
  transparency, accent color, contrast preference, or forced-colors mode through the real
  `WindowMetricsService` path could incorrectly stay cache-hit after the environment changed.

How it was exposed:

- Added a fixture-driven environment view-cache harness:
  `crates/fret-ui/src/declarative/tests/fixtures/environment_view_cache_invalidation_v1.json`
- Added a thin declarative runner:
  `crates/fret-ui/src/declarative/tests/environment_view_cache_harness.rs`
- The first run failed before the runtime fix:
  - `renders.env_cache` stayed at `1` instead of `2`.
  - `observed.env_unique_values` stayed at `1` instead of `2`.
  - Failures covered reduced motion, color scheme, contrast preference, forced colors, text scale,
    reduced transparency, and accent color.

What was fixed:

- `crates/fret-ui/src/declarative/mount.rs` now commits all known `WindowMetricsService`
  environment values into `ElementRuntime` before declarative rendering:
  - prefers reduced motion,
  - text scale factor,
  - prefers reduced transparency,
  - accent color,
  - color scheme,
  - contrast preference,
  - forced colors mode,
  - plus the existing scale factor, safe-area, and occlusion paths.

Regression coverage:

- Fixture suite:
  `crates/fret-ui/src/declarative/tests/fixtures/environment_view_cache_invalidation_v1.json`
- Fixture runner: `crates/fret-ui/src/declarative/tests/environment_view_cache_harness.rs`
- Existing focused environment tests: `crates/fret-ui/src/declarative/tests/environment_queries.rs`
- Runtime commit point: `crates/fret-ui/src/declarative/mount.rs`
- Real source path: `fret_core::window::WindowMetricsService`

Run results:

- `cargo test --profile dev-fast -p fret-ui --lib mechanism_harness_environment_view_cache_invalidation_matches_oracles -- --nocapture`
  - Before fix: failed for 7 cases.
  - After fix: passed, 1 test.
- `cargo test --profile dev-fast -p fret-ui --lib environment_ -- --nocapture`
  - Result: passed, 12 tests.
- `cargo test --profile dev-fast -p fret-ui --lib view_cache -- --nocapture`
  - Result: passed, 58 tests.
- `cargo fmt --package fret-ui --check`
  - Result: passed.

Next slice recommendation:

- Move to hit-test/routing or overlay/focus next. The environment slice shows the harness is now
  capable of finding real mechanism bugs when it drives the same entry point as runners instead of
  direct internal state.

## F10: Focus restore recipe fixture exposed a barrier-filtered focus oracle bug

Layer: `crates/fret-mechanism-harness` oracle, with recipe-consumer coverage in
`ecosystem/fret-ui-shadcn`

Status: fixed and covered

What was found:

- The initial shadcn recipe fixture for dialog/popover/combobox Escape dismissal failed on the
  dialog case.
- Runtime recipe behavior was already correct: the existing focused dialog test restored focus to
  the trigger.
- The mechanism harness oracle was wrong for this state. `UiPredicateV1::FocusIs` selected the
  target through the normal barrier-filtered path. During a close transition, a pointer/modal
  barrier can still be present while focus containment has already been released and focus is
  restored to the trigger. The trigger existed and was focused, but the harness selector filtered it
  out before comparing focus ids.

What was fixed:

- `ObservedTree` now exposes `select_unfiltered` / `select_best_unfiltered` for oracle cases that
  must reason about runtime facts outside the current input barrier.
- `UiPredicateV1::FocusIs` now resolves its target with the unfiltered selector path.
- Normal selector predicates such as `Exists` continue using the barrier-filtered path.
- Added a focused harness unit:
  `focus_oracle_can_match_restored_focus_outside_pointer_barrier`.

What was added:

- Fixture suite: `ecosystem/fret-ui-shadcn/tests/fixtures/focus_restore_recipe_cases_v1.json`
- Thin recipe runner: `ecosystem/fret-ui-shadcn/tests/focus_restore_mechanism_harness.rs`

The initial fixture matrix covered:

- dialog Escape dismissal closing the open model and restoring trigger focus,
- popover Escape dismissal closing the open model and restoring trigger focus,
- combobox Escape dismissal closing the open model and restoring trigger focus.

## F14: Select pointer-open outside press was suppressed by a stale guard decision

Layer: `ecosystem/fret-ui-kit` select primitive policy, exposed through
`ecosystem/fret-ui-shadcn` select recipe harness

Status: fixed and covered

What was found:

- The select outside-press fixture failed when the select was opened through the real trigger
  pointer path, then dismissed by a second pointer id clicking outside.
- The open model stayed `true`: the outside pointer-up was treated as if it were the original
  trigger click-release that should be suppressed.
- Root cause: `SelectMouseOpenGuardState` cached the previous pointer-up decision only by tick id.
  The runtime intentionally tolerates same/adjacent ticks for duplicate routing of the same platform
  pointer-up, but a later outside click can also receive an adjacent tick. Without pointer-id
  scoping, the guard reused the stale `Suppress` decision for a different pointer id.

What was fixed:

- `SelectMouseOpenGuardState` now stores the last pointer-up pointer id.
- Cached pointer-up decisions are reused only when the new event has the same pointer id and the
  same/adjacent tick id.
- The select outside-press recipe fixture now uses the real trigger pointer-open path rather than a
  controlled-open fallback.

Run results:

- `cargo test --profile dev-fast -p fret-ui-kit --lib mouse_open_guard_pointer_up_decision_is_reusable_within_tick -- --nocapture`
  - Result: passed, 1 test.
- `cargo test --profile dev-fast -p fret-ui-shadcn --test focus_restore_mechanism_harness mechanism_harness_focus_restore_recipe_cases_match_oracles -- --nocapture`
  - Result: passed, 1 test.

## F15: Prevent-default outside-press matrix exposed select barrier handler accumulation

Layer: `ecosystem/fret-ui-shadcn` recipe-consumer parity, with confirmed fix in
`ecosystem/fret-ui-kit` select primitive policy

Status: fixed and covered

What was found:

- The first prevent-default matrix covered popover, select, dropdown-menu, and context-menu.
- Non-modal click-through surfaces need to prevent the paired `FocusOutside` request as well as the
  `OutsidePress` request if the intended outcome is "keep the overlay open while the underlay still
  receives focus/activation". This is consistent with the existing focus-outside policy path.
- The select modal prevent-default case failed with `dismiss.calls == 15` instead of `1`.
- Root cause: `select_modal_layer_elements_with_pointer_up_guard_and_dismiss_handler` installed the
  modal barrier dismissal hook with `pressable_add_on_pointer_up` on every rendered open frame. A
  long-lived open select therefore accumulated one handler per frame.

What was fixed:

- The select modal barrier now uses `pressable_on_pointer_up` for its owned pointer-up dismissal
  behavior, replacing the previous accumulating `add` registration.
- The focus-restore recipe fixture now includes prevent-default cases for:
  - non-modal popover keep-open + underlay focus/activation,
  - modal select keep-open + underlay blocking,
  - non-modal dropdown-menu keep-open + underlay focus/activation,
  - modal dropdown-menu keep-open + underlay blocking,
  - non-modal context-menu keep-open + underlay focus/activation.
- The runner records `dismiss.calls` to catch repeated-handler accumulation instead of only checking
  final open state.
