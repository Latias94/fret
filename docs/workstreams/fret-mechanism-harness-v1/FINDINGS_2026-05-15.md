## F80: Accordion expanded-state mutation needed a first-class runtime predicate

Layer: diagnostics protocol/runtime predicate, synthetic oracle, and shadcn Accordion runtime gate.

Status: fixed as harness capability and promoted into UI Gallery runtime evidence plus shadcn
conformance. No Accordion recipe defect was reproduced by the promoted gate.

What was found:

- The synthetic mechanism harness could already observe the `Expanded` semantics flag through
  `ObservedSemanticsFlag::Expanded`, but `UiPredicateV1` did not expose an `expanded_is` predicate.
- Runtime diagnostics scripts could therefore prove Accordion panel mount/unmount with
  `exists`/`not_exists`, but could not assert the Radix/Base UI accessibility invariant that the
  trigger's expanded semantics state mutates with the controlled/open state.
- UI Gallery already had a stable Accordion Usage toggle script and test ids, so this was a
  harness observability gap rather than a missing demo surface.

What was fixed:

- Added `expanded_is` to `UiPredicateV1`, `fret_diag_protocol::builder`, the synthetic mechanism
  oracle, and the bootstrap diagnostics predicate evaluator.
- Added protocol serialization and script roundtrip coverage.
- Upgraded `ui-gallery-accordion-usage-toggle.json` to start directly on the Accordion page, assert
  `expanded_is=true` initially, `expanded_is=false` after collapse, and `expanded_is=true` after
  reopening, while preserving the existing panel mount/unmount checks.
- Promoted the Accordion Usage toggle gate into `ui-gallery-shadcn-conformance` in addition to the
  existing runtime evidence suite.

## F82: Live-region semantics needed runtime predicates and a Sonner mutation gate

Layer: diagnostics protocol/runtime predicate, synthetic oracle, and shadcn Sonner runtime gate.

Status: fixed as harness capability and promoted into UI Gallery runtime evidence plus shadcn
conformance. No Sonner recipe defect was reproduced by the promoted gate.

What was found:

- The synthetic mechanism harness already observed live-region metadata through
  `ObservedSemanticsLive` and `ObservedSemanticsFlag::LiveAtomic`.
- Runtime diagnostics bundles already exported live-region metadata, but `UiPredicateV1` did not
  expose a structured way to assert `aria-live`/`aria-atomic` equivalents.
- Sonner's toast viewport already maps Radix/Sonner live-region semantics to
  `SemanticsFlags.live=Polite`; the missing piece was a runtime predicate and a promoted script that
  proves the live region appears while a toast is present and disappears after dismissal.

What was fixed:

- Added `UiSemanticsLiveV1`, `semantics_live_is`, and `semantics_live_atomic_is` to the diagnostics
  protocol and builder helpers.
- Added synthetic oracle support for the new predicates.
- Added bootstrap runtime predicate support and a focused predicate test.
- Added `ui-gallery-sonner-live-region-mutation.json`, which starts on the Sonner page, proves no
  live-region viewport exists before showing a toast, asserts `live=polite` and
  `live_atomic=false` while the toast is mounted, then proves the live region is removed after the
  toast is dismissed.
- Promoted the gate into `ui-gallery-sonner-docs`, `ui-gallery-shadcn-runtime-evidence`, and
  `ui-gallery-shadcn-conformance`.

## F83: Select selected-state gate exposed an overlay-click timing harness defect

Layer: diagnostics script stability, selected-state runtime evidence, and shadcn Select
conformance promotion.

Status: fixed as harness/script stability and promoted into runtime evidence. No Select recipe
defect was reproduced after the script waited for overlay placement and bounds.

What was found:

- `selected_is` was already available in the diagnostics protocol, bootstrap runtime predicate, and
  synthetic oracle, but the primary Select commit-and-label script did not assert selected-state
  mutation.
- The first upgraded runtime run failed before the selected-state assertion: after opening the
  Select overlay, the script clicked Banana before overlay placement/bounds were stable. The
  generated click landed at `y=0`, and the label stayed on the previous value
  (`Selected: blueberry` in the failure bundle).
- This was a harness defect: a script can have stable test IDs and still be too early for self-drawn
  overlay geometry if it skips the placement/bounds gate before clicking.

What was fixed:

- Added protocol serialization coverage for `selected_is`.
- Added script roundtrip coverage for
  `tools/diag-scripts/ui-gallery/select/ui-gallery-select-commit-and-label-update.json`.
- Upgraded the Select commit-and-label script to wait for `wait_overlay_placement_trace` and
  `bounds_within_window` before the item click, then reopen the popup and assert
  `selected_is=true` for Banana plus `selected_is=false` for Apple.
- Promoted the script into `ui-gallery-shadcn-conformance`; it was already part of
  `ui-gallery-shadcn-runtime-evidence`.
