# Findings 2026-05-14

## F61: Hidden semantics were still selectable by default harness oracles

Layer: `crates/fret-mechanism-harness` observation/oracle semantics filtering +
`crates/fret-ui` declarative semantics fixture coverage

Status: fixed and covered

What was found:

- The semantics metadata fixture had already grown beyond the coverage map: value/editing metadata,
  collection metadata, action surfaces, live-region metadata, numeric metadata, and scroll metadata
  were present and passing.
- The remaining real semantics gap was hidden-subtree policy from ADR 0293. `SemanticsSnapshot`
  intentionally keeps hidden nodes for deterministic diagnostics, but default harness selectors
  should model the filtered accessibility tree.
- `ObservedTree::select_best` filtered invisible roots and input barriers, but did not filter
  `SemanticsFlags.hidden` or descendants of hidden nodes. This could let mechanism fixtures
  incorrectly treat `aria-hidden` / hidden diagnostic nodes as user-facing accessibility matches.
- `semantics_flag_is` also used the default filtered path, so a correct hidden-subtree filter would
  have made it impossible to assert the hidden flag on retained diagnostic nodes.

What was fixed:

- `ObservedTree::node_is_selectable` now excludes nodes whose own semantics flag is hidden or whose
  ancestor is hidden.
- `semantics_flag_is` now uses the unfiltered selector path so diagnostics can still assert hidden
  flags and inspect retained nodes inside hidden subtrees.
- Added a focused harness regression:
  `default_selectors_exclude_semantics_hidden_subtrees_but_flags_remain_queryable`.
- Extended `semantics_relations_v1.json` with
  `hidden-subtree-policy-excludes-default-selectors-but-keeps-diagnostics`, backed by a real
  declarative `SemanticsProps` scenario.

Run results:

  - Result: passed, 1 test.

  - Result: passed, 1 test.

## F62: Scroll/virtual-list runtime gates needed structured instability oracles

Layer: diagnostics protocol + bootstrap script runner + UI Gallery runtime gates

Status: fixed and covered

What was found:

- The Virtual List small-scroll diagnostics script was not a durable runtime gate. It targeted the
  dev-only Virtual List Torture page without recording the `gallery-dev` precondition, and it
  initially used `ui-gallery-virtual-list-root` where the live scroll semantics were actually on
  `ui-gallery-content-viewport-virtual_list_torture`.
- The existing Checkbox RTL scripts could prove "eventually stable" at a short boundary, but could
  not assert "no-input idle stability for N frames." That left the user's RTL scroll jitter report
  hard to convert into a reusable mechanism harness gate.
- The first implementation of idle-stability evidence exposed a second harness defect: the new
  trace was recorded during the assertion, but `note_step_start_and_scope_evidence` dropped it when
  the following capture step started, so passed script results lost the structured sampling proof.
- Current runtime evidence did not reproduce a real RTL scroll mechanism defect on the default
  Checkbox page. The new gate sampled 45 idle frames with no scroll drift.

What was fixed:

- Added `UiPredicateV1::VirtualListWindowShiftSamplesLenLe` so virtual-list debug telemetry can be
  asserted directly from diagnostics scripts.
- Hardened `ui-gallery-virtual-list-small-scroll-no-window-shifts.json` with feature metadata,
  stable navigation, the correct scroll semantics target, diagnostic resets, and `max=0` window-shift
  assertions before and after small wheel deltas.
- Added `assert_semantics_scroll_idle_stable` to diagnostics script v2. It samples a structured
  semantics scroll field for a fixed no-input frame window and fails when single-frame or total
  drift exceeds configured thresholds.
- Added `UiSemanticsScrollIdleStableTraceEntryV1` evidence and retained it across later capture
  steps so passed scripts keep their final sampling proof.
- Promoted `ui-gallery-checkbox-scroll-to-rtl-field.json` into `ui-gallery-rtl-smoke` and
  `ui-gallery-shadcn-conformance`.

## F63: ScrollArea/Table RTL needed idle-stability runtime companions

Layer: diagnostics scripts + UI Gallery runtime gates

Status: covered; no mechanism defect reproduced on these surfaces

What was found:

- The existing Checkbox RTL idle-stability gate covered only the default page content viewport after
  scrolling to an RTL section. That was useful, but it did not cover a nested RTL scroll root where
  inner scroll offset, outer page scroll offset, and RTL layout direction can interact.
- The existing ScrollArea RTL diagnostics script was screenshot-only. It proved the demo could be
  reached, but it did not assert that scrolling the nested RTL viewport settled after scripted input.
- The Table page had stable RTL title/row anchors from `ui-gallery-table-docs-smoke`, but no
  idle-stability gate that sampled the outer Gallery content viewport after scrolling to the RTL
  table section.
- The user's fresh "scroll to a place in RTL and the page keeps moving up/down" report therefore
  still had an obvious harness gap even though the Checkbox RTL gate was green.

What was fixed:

- Added `ui-gallery-scroll-area-rtl-idle-stability.json`, which navigates to the Scroll Area page,
  scrolls the RTL ScrollArea into view, scrolls the nested RTL viewport, then samples both the inner
  `ui-gallery-scroll-area-rtl-viewport` and the outer `ui-gallery-content-viewport` for 60 no-input
  frames.
- Added `ui-gallery-table-rtl-idle-stability.json`, which navigates to the Table page, scrolls the
  RTL table section into view, waits for the RTL title and final invoice row to settle, then samples
  the outer `ui-gallery-content-viewport` for 60 no-input frames.
- Promoted the gate into both `ui-gallery-rtl-smoke` and `ui-gallery-shadcn-conformance`.
- Regenerated `tools/diag-scripts/index.json`.

## F64: Virtual-list boundary ownership was split across event, prepaint, and retained reconcile paths

Layer: `crates/fret-ui` virtual-list event handling, layout-state scroll consumption, prepaint
window attribution, retained host reconcile, plus `fret-workspace` render-time model writes that
polluted view-cache diagnostics.

Status: fixed and covered for focused mechanism gates; retained runtime suite wrapper clean-exit
still needs a follow-up check.

What was found:

- The boundary-crossing virtual-list diagnostics exposed a real owner split. Non-retained
  `VirtualList` wheel handling called `cx.notify()` when the visible range escaped the rendered
  window, so render could commit the new window before prepaint observed the old rendered window plus
  new offset transition. That made prepaint ownership and reason attribution unreliable.
- Retained virtual-list reconcile preferred cached prepaint/render windows even when a programmatic
  scroll-handle offset change scheduled reconcile without a preceding prepaint pass. That could keep
  stale retained rows after a boundary-crossing scroll.
- Final scroll-handle baseline consumption still needed a non-retained cache-root dirty fallback
  for revision-only or paint-before-prepaint paths where no later prepaint owner would invalidate the
  stale rendered window.
- Prepaint reason attribution could report `Unknown` when an earlier binding pass had already copied
  the new offset into `VirtualListState`, even though the stale render window no longer covered the
  current visible range.
- `WorkspacePaneContentFocusTarget` and `WorkspaceCommandScope` performed render-time no-op
  `ModelStore::update` calls. Because `ModelStore::update` always dirties the model, these writes
  polluted view-cache/root-boundary diagnostics and obscured actual cache owner changes.

What was fixed:

- Non-retained virtual-list wheel events no longer notify the view-cache root on boundary escape;
  prepaint owns the stale-window plus new-offset observation. Retained hosts still mark retained
  reconcile from the event path.
- Retained virtual-list reconcile now reuses a cached window only while it covers the current
  visible range; otherwise it derives a new retained window from the current scroll offset.
- Final scroll-handle baseline consumption directly dirties the non-retained cache root when it is
  the last owner path available.
- `VirtualListPrepaintWindowUpdate` now carries the current visible range, and prepaint falls back
  to `ScrollOffset` reason attribution when the rendered window no longer covers that visible range.
- Workspace focus registry/scope components now read first and only update models when the stored
  value actually changes.
