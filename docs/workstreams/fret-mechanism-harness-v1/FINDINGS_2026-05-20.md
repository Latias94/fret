## F235: View Cache dynamic text mutation is now a runtime oracle

Layer: UI Gallery View Cache harness diagnostics plus `fret-diag-protocol` script roundtrip.

Status: diagnostics hardening complete. No new view-cache, text-cache, or layout defect was
reproduced.

What was found:

- The existing View Cache runtime gate proved cached-subtree counter mutation and Popover
  open/close state, but it did not force a cached subtree to change visible wrapped text and
  following layout in the same run.
- That left a gap after the recent text-cache repair work: a stale prepared text blob or stale
  cached subtree layout could still hide behind app-snapshot-only counter assertions.

  an `8px` gap between the Popover trigger and the retained list. Runtime evidence showed those

## F236: HitTestOnly paint-cache replay is now a runtime oracle

Layer: diagnostics protocol/runtime predicates, UI Gallery mechanism harness, and diagnostics suite
registration.

script was promoted into a real runtime gate.

## F237: Moved cache-root hit routing rejects stale root-only path reuse

Layer: `fret-ui` tree prepaint interaction cache and hit-test path-cache reuse.

Status: focused mechanism hardening complete. No stale hit-routing defect was reproduced; the
existing cached-path fallback already protects this root-only case.

What was found:

- The previous moving cache-root regression intentionally cleared `ui.hit_test_path_cache` before
  moving the cache root. That locked interaction-record translation, but it did not prove a cached
  root-only hit path from the previous pointer position could not hide a child that moved under the
  same pointer on the next frame.
- The new focused scenario first primes a root-only cached path by hit-testing a point inside the
  root but outside the cached child. It then moves the clean view-cache root and its leaf under that
  same point, reuses translated interaction records through prepaint, and hit-tests again without
  clearing the path cache.
- A stale-path bug would return the root again. Current runtime correctly rejects the root-only
  cached path because it ends at a node with hit-testable children, falls back to full hit testing,
  and returns the moved leaf. The regression also asserts the hit-test path-cache miss counter
  increments, so the guard proves the fallback path rather than merely accepting a lucky hit.

What was changed:

- Added `prepaint_interaction_cache_root_move_invalidates_stale_root_only_hit_path` to
  `crates/fret-ui/src/tree/tests/prepaint.rs`.
- The test complements `prepaint_interaction_cache_replay_translates_records_when_cache_root_moves`
  by keeping the path cache live across the cache-root move.

## F238: Hit-test path cache rejects stale lower-child paths when z-order changes under pointer

Layer: `fret-ui` tree hit-test path-cache reuse.

Status: focused mechanism hardening complete. No stale z-order routing defect was reproduced; the
existing higher-z sibling guard already rejects this class of cached-path reuse.

What was found:

- F237 covered a root-only cached path, but the more dangerous cached-path shape is a child path:
  pointer routing can cache `root -> lower_child`, then a higher-z sibling can move under the same
  pointer. If the cached child path were blindly accepted, runtime pointer routing would keep
  sending events to the lower child while fallback hit testing would choose the newly moved higher
  sibling.
- The new focused guard primes the cached path to the lower child, moves the higher sibling over
  the same point, and re-hits without clearing the path cache.
- Current runtime correctly scans higher-z siblings before accepting the cached child path. The
  stale path misses, fallback hit testing returns the higher sibling, and the refreshed path is then
  cache-reusable on the next query.

What was changed:

- Added `hit_test_layers_cached_rejects_stale_path_when_higher_z_sibling_moves_under_pointer` to
  `crates/fret-ui/src/tree/tests/hit_test.rs`.
- The test asserts both the miss counter on stale reuse and the hit counter after the fallback
  refreshes the path to the moved higher-z sibling.
