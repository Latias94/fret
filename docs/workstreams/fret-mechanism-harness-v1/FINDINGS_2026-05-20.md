## F235: View Cache dynamic text mutation is now a runtime oracle

Layer: UI Gallery View Cache harness diagnostics plus `fret-diag-protocol` script roundtrip.

Status: diagnostics hardening complete. No new view-cache, text-cache, or layout defect was
reproduced.

What was found:

- The existing View Cache runtime gate proved cached-subtree counter mutation and Popover
  open/close state, but it did not force a cached subtree to change visible wrapped text and
  following layout in the same run.
- That left a gap after the recent text-cache repair work: a stale prepared text blob or stale
  cached subtree layout could still hide behind app-snapshot-only counter assertions.
- The first dynamic-text gate draft over-constrained the existing CardContent layout by requiring
  an `8px` gap between the Popover trigger and the retained list. Runtime evidence showed those
  two controls are adjacent but non-overlapping by current shadcn CardContent semantics, so the
  durable oracle is non-overlap there while the new dynamic text keeps a stricter `8px` gap before
  the following Popover trigger.

What was changed:

- Added a dynamic text probe to the View Cache harness page. `counter=0` renders a short baseline,
  while `counter>0` renders a longer wrapped sentence inside the cached subtree.
- Added `/view_cache/dynamic_text_len` and `/view_cache/dynamic_text_wrapped` app-snapshot fields.
- Added `ui-gallery-view-cache-dynamic-text-mutation-through-cache.json` with a root redirect,
  suite membership, registry entry, layout/screenshot/bundle captures, text trace assertion,
  visible label assertion, and geometry non-overlap checks.
- Added direct protocol roundtrip coverage for the new script.

## F236: HitTestOnly paint-cache replay is now a runtime oracle

Layer: diagnostics protocol/runtime predicates, UI Gallery mechanism harness, and diagnostics suite
registration.

Status: diagnostics hardening complete. No paint-cache key-mismatch defect was reproduced after the
script was promoted into a real runtime gate.

What was found:

- The existing `ui-gallery-hit-test-only-paint-cache-probe-sweep.json` was a weak local capture
  script: it did not carry `gallery-dev` launch metadata, did not navigate to the hidden UI Gallery
  mechanism page, and did not assert the paint-cache counters that distinguish a true
  `HitTestOnly` replay from a normal repaint.
- The first focused run timed out on the default Overlay page while waiting for
  `ui-gallery-hit-test-only-probe-region`, proving the script was not self-contained.
- The first promoted suite run found a real diagnostics hygiene defect in the probe page: the
  outer panel and the inner region shared `ui-gallery-hit-test-only-probe-region`. The suite lint
  failed on `semantics.duplicate_test_id`, so the outer panel now uses
  `ui-gallery-hit-test-only-probe-panel` and the hit region keeps the stable region id.
- The first app-snapshot oracle used `/shell/selected_page`, but UI Gallery publishes the selected
  page at `/selected_page`. The corrected gate now verifies it reached
  `hit_test_only_paint_cache_probe` before resetting diagnostics and sweeping the pointer.

What was changed:

- Added first-class protocol predicates for
  `paint_cache_hit_test_only_replay_allowed_ge` and
  `paint_cache_hit_test_only_replay_rejected_key_mismatch_le`.
- Exported the corresponding `UiFrameStatsV1` counters through the bootstrap diagnostics snapshot
  and evaluated the predicates against recent debug snapshot history.
- Upgraded the UI Gallery script with `gallery-dev` metadata, `FRET_UI_GALLERY_PAINT_CACHE=1`
  defaults, nav-search page selection, the corrected app-snapshot pointer, counter assertions,
  region geometry assertions, and bundle capture.
- Added the `ui-gallery-hit-test-only-paint-cache` suite with zero-warning lint policy plus direct
  protocol roundtrip coverage for the promoted script.
