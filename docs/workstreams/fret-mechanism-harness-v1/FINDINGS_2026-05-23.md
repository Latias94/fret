# Findings - 2026-05-23

## F268: Moving cached Combobox disabled action-state stayed green with an explicit cache-key contract

Context:

- F267 closed the moving cached Combobox Escape focus-restore gap and recommended continuing on
  stale action-state/disabled metadata.
- The important contract here is not "stateful cached subtrees update magically." For
  state-sensitive cached subtree contents, the component layer must include the state in the
  explicit cache key. This slice intentionally proves the correct contract instead of relying on an
  unkeyed stale-cache misuse.

What was found:

- No new mechanism or recipe defect was reproduced.
- The new gate is still useful because visual placement and focus can both pass while an item keeps
  stale accessibility/action metadata. The runtime now proves the moved cached Combobox reopens with
  the updated `In Review` item state: `disabled=true` and `invoke=false`.

What was changed:

- Extended the diagnostics-only moving cached Combobox fixture with an `In Review` disabled-state
  toggle and an observable `review-disabled-state` status node.
- Added the disabled state to the cached subtree key using a stable `fret_ui::cache_key::mix(...)`
  seed so the cached subtree is explicitly invalidated when the action-state surface changes.
- Added
  `ui-gallery-resizable-view-cache-moving-combobox-disabled-action-state.json`, promoted it into
  `ui-gallery-resizable`, added protocol roundtrip coverage, and refreshed the diagnostics script
  registry.
