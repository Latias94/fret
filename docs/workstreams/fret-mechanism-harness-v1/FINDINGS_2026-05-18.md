## F171: Pressable absolute-only wrapper envelopes now drive layout bounds

Layer: `fret-ui` layout engine and passthrough wrapper measurement.

Status: real mechanism defect found and fixed.

What was found:

- `Pressable` is a behavioral passthrough wrapper, but the layout engine previously modeled an
  auto-sized wrapper with only absolute-positioned children as an ordinary grid/block container.
- Taffy correctly ignores absolute-positioned children for normal flow intrinsic contribution, so
  the wrapper's solved layout bounds collapsed to `0 x 0`.
- The widget-local layout fallback could still place the absolute child and hit-test the visible
  child after later fixes, but `UiTree::debug_node_bounds()` and the parent layout envelope still
  reported the `Pressable` wrapper as `0 x 0`.
- The fixture uses a single absolute child with `left: 25%`, `top: 10%`, and `20 x 10` size. The
  required wrapper envelope is `27 x 12`, which places the child at `(6.75, 1.2)` and keeps a
  near-edge hit-test sample inside the child.

What was changed:

- Added `pressable-fractional-absolute-child-envelope-matches-layout` to
  `layout_primitives_v1.json`.
- Added the matching `PressableFractionalAbsoluteChildEnvelopeMatchesLayout` harness scenario,
  scalar layout/measurement metrics, and near-edge hit-test sample.
- Updated passthrough wrapper measurement so absolute-only wrappers contribute the shared
  absolute-child envelope even during final definite layout probes, not only placeholder or
  intrinsic probes.
- Updated the flow engine so an auto/auto wrapper with only absolute children is measured as a
  leaf for parent flow sizing. This is intentionally scoped to absolute-only auto wrappers and does
  not change fixed containing-block percent inset semantics.

## F191: Retained Table direct-start header bounds converge after flex sibling snapshots

Layer: `fret-ui` flex layout mechanism plus UI Gallery retained Table direct-start regression.

Status: confirmed mechanism defect fixed. The selected-state runtime companion now reaches the row
click path, where a separate hit-test/routing follow-up remains.

What was found:

- F190's runtime companion timed out before selected-state assertions because
  `ui-gallery-table-retained-header-row` stayed at `0,0 0x0` even though the retained Table subtree
  existed.
- The root cause was not Table selection semantics or a recipe workaround. It was the flex final
  layout path: `layout_flex_impl_engine` queried later sibling rects from the layout engine while it
  was recursively laying out earlier children. That recursive child layout could invalidate later
  sibling solved stamps, so later siblings no longer had authoritative rects when the final
  `layout_in` pass reached them.
- The visible runtime symptom was a retained Table subtree that existed but skipped final layout and
  collapsed to `0 x 0` on direct Gallery startup.

What was changed:

- `layout_flex_impl_engine` now snapshots the ordered child layout rects before recursively calling
  `layout_in` on any child.
- Auto-margin tail sizing, gap preservation, shift application, and the final child layout loop all
  read from that snapshot instead of re-querying live sibling rects after recursive layout begins.
- Added `table_retained_torture_direct_start_header_bounds_converge` under `gallery-dev` to prove
  the retained Table header row reaches non-zero bounds from a direct page start.
