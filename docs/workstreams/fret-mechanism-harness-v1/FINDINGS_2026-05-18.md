# Findings - 2026-05-18

## F170: Flex wrap gap layout and definite-width max-content measurement are now covered

Layer: `fret-ui` layout primitive fixture harness.

Status: coverage gap closed; no new flex wrap/gap layout or intrinsic measurement defect
reproduced.

What was found:

- F169 proved single-line flex `gap` layout/measurement consistency, but wrapping rows remained a
  higher-risk split because the same `gap` value contributes to both main-axis item spacing and
  cross-axis line spacing.
- The useful mechanism question was whether a definite-width wrapped flex row reports the same
  envelope through final layout and `measure_in(MaxContent)` after the second line is created.
- The new fixture uses a 68px-wide horizontal flex row with `wrap=true`, `gap=8`, and children
  `30 x 10`, `30 x 12`, and `20 x 14`. The first two children occupy the first line
  (`30 + 8 + 30 = 68`), and the third child wraps to `y=20` (`12 + 8`).

What was changed:

- Added `flex-wrap-gap-measure-matches-layout` to `layout_primitives_v1.json`.
- Added the matching `FlexWrapGapMeasureMatchesLayout` harness scenario and scalar metrics for
  final layout bounds plus definite-width `measure_in(MaxContent)`.
- No runtime behavior change was needed. The current flex layout and measurement paths agree on
  the `68 x 34` wrapped gap envelope.

## F171: Pressable absolute-only wrapper envelopes now drive layout bounds

Layer: `fret-ui` layout engine and passthrough wrapper measurement.

Status: real mechanism defect found and fixed.

What was found:

- `Pressable` is a behavioral passthrough wrapper, but the layout engine previously modeled an
  auto-sized wrapper with only absolute-positioned children as an ordinary grid/block container.
- Taffy correctly ignores absolute-positioned children for normal flow intrinsic contribution, so
  the wrapper's solved layout bounds collapsed to `0 x 0`.
- The widget-local layout fallback could still place the absolute child and hit-test the visible
  child after later fixes, but `UiTree::debug_node_bounds()` and the parent layout envelope still
  reported the `Pressable` wrapper as `0 x 0`.
- The fixture uses a single absolute child with `left: 25%`, `top: 10%`, and `20 x 10` size. The
  required wrapper envelope is `27 x 12`, which places the child at `(6.75, 1.2)` and keeps a
  near-edge hit-test sample inside the child.

What was changed:

- Added `pressable-fractional-absolute-child-envelope-matches-layout` to
  `layout_primitives_v1.json`.
- Added the matching `PressableFractionalAbsoluteChildEnvelopeMatchesLayout` harness scenario,
  scalar layout/measurement metrics, and near-edge hit-test sample.
- Updated passthrough wrapper measurement so absolute-only wrappers contribute the shared
  absolute-child envelope even during final definite layout probes, not only placeholder or
  intrinsic probes.
- Updated the flow engine so an auto/auto wrapper with only absolute children is measured as a
  leaf for parent flow sizing. This is intentionally scoped to absolute-only auto wrappers and does
  not change fixed containing-block percent inset semantics.

## F172: Pressable mixed flow/absolute wrapper envelopes now agree across layout, measure, and hit-test

Layer: `fret-ui` layout engine, passthrough wrapper measurement, and positioned-container layout.

Status: real mechanism defect found and fixed.

What was found:

- F171 fixed the absolute-only case, but a higher-risk mixed case remained: an auto/auto behavioral
  wrapper with one normal flow child and one absolute child extending beyond the flow child.
- `pressable-mixed-flow-absolute-child-envelope-matches-layout` first failed because the wrapper's
  authoritative layout bounds and placeholder measurement stayed at the flow child's `20 x 10`
  size, while the absolute child required a `34 x 12` envelope.
- After the first measure/flow fix, wrapper bounds were correct but final child layout still reused
  a too-small absolute containing block, placing the child at `(5, 1)` with a `20 x 10` width
  instead of `(8.5, 1.2)` with its declared `25 x 10` size. The near-edge hit-test sample landed
  on the parent wrapper instead of the absolute child.
- The fixed containing-block percent inset case stayed protected by the existing
  `absolute-inset-fraction-resolves-against-containing-block` fixture.

What was changed:

- Added `pressable-mixed-flow-absolute-child-envelope-matches-layout` to
  `layout_primitives_v1.json`.
- Added the matching `PressableMixedFlowAbsoluteChildEnvelopeMatchesLayout` harness scenario,
  scalar layout/measurement metrics, and near-edge hit-test sample.
- Updated passthrough wrapper measurement so auto axes include absolute-child envelopes even when a
  normal flow child already contributes a non-zero size.
- Updated auto/auto passthrough flow modeling so wrappers with absolute children are measured as
  leaves for parent flow sizing.
- Updated positioned-container fallback layout so auto wrappers union flow-child size with
  absolute-child envelope size, then place static flow children using their measured size and
  absolute children against the union envelope.
