# Findings - 2026-05-22

## F262: Command disabled active-descendant coverage had promotion/serialization debt, not a new recipe defect

Context:

- F261 recommended returning to Command because it is the main action-state comparison point that
  uses active-descendant/list semantics instead of roving menu focus.
- The codebase already had two strong Command rows: a direct disabled-focusable keyboard
  suppression gate and a retained/windowed active-descendant action-state mutation gate.

What was found:

- No new Command recipe/runtime defect was reproduced. The direct disabled-focusable gate already
  proves the intended invariant: default disabled rows are skipped, opt-in disabled-focusable rows
  can become active descendants, the active disabled row exports `disabled=true` and
  `invoke=false`, and Enter does not dispatch the row action.
- The durable gap was suite and schema coverage. The retained/windowed mutation row was already in
  `ui-gallery-shadcn-runtime-evidence` and had protocol roundtrip coverage, but the direct
  disabled-focusable row was only in the Command and shadcn conformance suites and lacked a
  dedicated protocol roundtrip.
- A first fresh focused runtime run with the default `300000ms` harness timeout timed out while the
  script was still progressing through long Command-page startup/click-stable work; the captured
  bundle showed the target page/input existed and the script was still at step 8. Re-running with a
  larger timeout completed and passed, so this is recorded as harness-time-budget evidence rather
  than a Command failure.
