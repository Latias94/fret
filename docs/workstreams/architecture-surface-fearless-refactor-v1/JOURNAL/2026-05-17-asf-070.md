# ASF-070 — Renderer Facade Decision

Date: 2026-05-17
Status: Complete

## Decision

Keep `crates/fret-render` as the curated default renderer facade. Do not collapse it into
`crates/fret-render-wgpu`.

## Rationale

The closed `docs/workstreams/renderer-modularity-fearless-refactor-v1/` lane already reached the
shape this architecture lane wants: `fret-render` is not a wildcard backend dump, but a documented
default facade with explicit v1 buckets.

Evidence:

- `crates/fret-render/src/lib.rs` lists the stable facade buckets and keeps backend-only diagnostics
  behind direct `fret-render-wgpu` imports.
- `crates/fret-render/tests/facade_surface_snapshot.rs` locks the facade buckets in a compile gate.
- `crates/fret-render-wgpu/tests/host_provided_gpu_topology_smoke.rs` proves the engine-hosted,
  direct GPU topology, so `WgpuContext` remains a convenience path rather than the only path.
- `docs/workstreams/renderer-modularity-fearless-refactor-v1/CLOSEOUT_AUDIT.md` closes the v1
  renderer-modularity lane with first-party callers aligned to the curated facade story.

Collapsing `fret-render` now would remove a useful integration boundary and force app/runner
callers to depend on backend-specific details even when they only need the default renderer
contract. Future renderer semantic or capability work should open a renderer-specific follow-on
rather than widening this architecture-surface lane.
