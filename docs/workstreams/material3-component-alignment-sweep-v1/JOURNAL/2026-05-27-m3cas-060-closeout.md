# M3CAS-060 Closeout

Date: 2026-05-27

## Summary

Closed the DatePicker/TimePicker packet. The main issue was not picker overlay/focus policy or a
shared Material foundation gap. The actionable drift was selector and diagnostics hygiene plus stale
date/time headless goldens that still encoded stretched modal underlay/action geometry.

## Changes

- DatePicker now derives dotted part ids from the caller-provided base:
  root chrome, modal scrim/chrome/panel, docked/modal nav buttons, day cells, and dialog actions.
- TimePicker now derives dotted part ids from the caller-provided base:
  root chrome, mode toggle, hour/minute selectors, dial chrome, period buttons, input fields, modal
  scrim/chrome/panel, and dialog actions.
- Updated TimePicker interaction tests and the UI gallery chrome-fill diagnostic to use the new
  base-derived ids.
- Added picker coverage to `automation_surface`.
- Refreshed all date/time picker headless goldens after classifying stale modal underlay/action
  stretch drift.
- Updated the alignment matrix and packet evidence.

## Layer Classification

- `material_recipe`: picker state, draft commit/cancel, calendar grid, time dial/input modes, and
  stable part ids.
- `kit_policy`: modal overlay request, scrim dismiss, focus trap, and focus restore through existing
  overlay/focus primitives.
- `test_harness`: stale date/time modal underlay/action stretch goldens.
- `diagnostics`: old global/hyphen picker selectors.
- `follow_on`: richer calendar/time-grid accessibility depth.
