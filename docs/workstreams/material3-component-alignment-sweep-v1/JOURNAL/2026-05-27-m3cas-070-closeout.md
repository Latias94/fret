# M3CAS-070 Closeout - Overlay And Feedback

Date: 2026-05-27

## Summary

Closed the overlay/feedback packet for Menu, DropdownMenu, Dialog, BottomSheet, Tooltip, and
Snackbar. The task did not justify moving overlay/focus policy into Material recipes. Shared
dismissal, focus trap/restore, tooltip delay, safe-hover, and toast live-region behavior remain in
`fret-ui-kit`.

## Changes

- Added or confirmed stable dotted part ids for menu/dropdown menu surfaces and items.
- Changed Dialog modal part ids to dotted `scrim`, `scrim.chrome`, `panel`, and `panel.chrome`.
- Added `SemanticsRole::Dialog` to the Dialog panel.
- Changed BottomSheet derived ids to dotted scrim/sheet/drag-handle selectors.
- Added `test_id` support for `PlainTooltip`, `RichTooltip`, and `Snackbar`.
- Added overlay/feedback automation surface coverage, bringing the diagnostics test target to 15
  tests.
- Repaired the DropdownMenu outside-press test harness so the underlay probe is actually outside
  the open menu.
- Refreshed snackbar, menu-dialog-style, and bottom-sheet headless goldens after classifying stale
  drift.

## Layer Decisions

- `material_recipe`: stable Material selectors, visual chrome, and component composition.
- `kit_policy`: dismiss/focus policy, tooltip delay/safe-hover, and toast live-region/action
  policy.
- `test_harness`: stale selector drift, dropdown outside-press probe placement, and headless
  golden drift.
- `mechanism_follow_on`: rich tooltip interactivity if Material decides rich tooltip actions must
  receive pointer input.

## Follow-Ons

- Add a layout-safe semantic alias/test-id mechanism or explicit component sizing decision before
  adding bottom sheet `.chrome` aliases.
- Decide rich tooltip interactivity through an ADR-backed overlay mechanism follow-on.
- Add kit-level toast action/close part ids only if Snackbar subpart automation becomes necessary.
- De-duplicate plain/rich tooltip test-id wiring after selector behavior remains stable.
